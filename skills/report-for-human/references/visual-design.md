# 视觉配方：从 Piano 发布地图复现

目标是同一家族的成品，而非像素临摹。`assets/reference-report.html` 是去项目化完整样例；`assets/reference-preview.png` 是该样例的真实浏览器渲染。示例事实均为虚构，不可用来证明真实系统状态。

## 固定的视觉语言

| 部位 | 采用的规则 | 目的 |
| --- | --- | --- |
| 画布与容器 | 浅灰底、白色面板、约 1180px 宽；24px 圆角、24–32px 留白 | 让主图有空间，避免密集控制台感 |
| 首屏 | 左侧结果标题与短回答，右侧一个深蓝结论区；窄屏变单列 | 先告诉读者现在该怎么看 |
| 文字层级 | 12px 标记、32–44px 标题、16px 正文；每段约两三行 | 用字号和空白组织阅读，不堆粗体 |
| 色彩 | 蓝色强调结论，紫/绿等辨认参与方；状态同时有文字 | 颜色标记职责，不把某一参与方永久画成失败方 |
| 主视觉 | 前后对照、要求链、阶段条、分支责任图四选一 | 图必须回答问题，箭头必须携带含义 |
| 证据 | 一处原生折叠区，固定版本、时间、来源、验证边界 | 保持首屏轻，仍可追溯 |

## 六步复现

1. 打开完整样例，确认标题、深色结论区和大面积主图的比例；阅读与当前任务最接近的 JSON 示例。
2. 先写一句有证据的结果与最重要未知；用读者的话命名，不用文件名作标题。
3. 只填与主问题有关的前后差异、要求、阶段或节点/箭头。先让关系准确，再调版面。
4. 用 `render_report.py` 生成。保留首屏双栏与单一主面板，不添加侧栏、统计卡墙、卡片套卡片或无意义装饰。
5. 对复杂任务加一个辅助图或少量场景切换；它必须改变关系、分支或结论。参与方颜色保持一致，事实/推断/未知/模拟另用明确标签。
6. 查看桌面及手机截图，逐项点击后再打印检查。读者十秒内应能复述“结果、卡点、下一步”。

## 内容与美观的验收

- 首屏：标题是结果、短回答可独立阅读、关键限制可见；深色区只有一个重点，不堆四个 KPI。
- 主图：箭头有事件/数据/条件；并行路径、控制方与展示方真实区分。把文字卡片排一排不自动构成流程。
- 复杂度：普通报告一个主视觉即可；可见文字默认约 250–600 字，不把正文搬进十张卡片来规避精简。
- 手机：文字可读、关系保持；优先重排，复杂 SVG 使用可读的同内容窄屏关系视图。整页不横向溢出。
- 可访问：焦点清楚、按钮至少 44px、状态不只靠颜色；系统暗色、减少动态效果与打印均有样式。
- 真实性：示例的日期、版本、参与方、品牌和链接都已替换；不以效果图或模板合成数据冒充现场复现。

自定义 HTML 时仍内联随附主题与布局，使用 `.human-report` 的组件。样例是设计锚点，不是每份报告必须填满的章节清单。
