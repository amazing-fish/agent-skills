# 宽表和列宽

表格用于跨行、跨列比较，不是正文的默认容器。先按列的角色分配空间：名称或状态列较短，解释、影响、证据列需要更多宽度；路径列须允许换行。不要对所有表前两列设 `width:1%`、`nowrap`，也不要把所有表等分或统一套一个最小宽度。

简单表先用浏览器自动布局。长文比较表可用下面的显式列比例，在较窄容器中局部横向滚动；各行独立且跨列比较不重要时，优先重排成带字段名的条目。不要缩小手机字体来容纳桌面表。横向滚动须有可聚焦容器、可理解的名称和可见提示，不能只依赖滚动条。

## 长表的可选增强

`add_report_controls.py` 内联共用表格样式与交互。使用 `rfh-table-wrap` + `rfh-table`，把默认比例写在原生 `<colgroup>` 中，把本表所需的最小宽度写在 `--rfh-table-min-width` 中。下例是虚构内容，比例和宽度只是该表的起点，不是全局标准。

```html
<p>窄屏可横向滚动；需要更多空间时可调整列宽。</p>
<div class="table-wrap rfh-table-wrap" role="region" aria-label="组件责任对照" tabindex="0">
  <table class="rfh-table" data-rfh-resizable style="--rfh-table-min-width:680px">
    <caption>组件责任对照</caption>
    <colgroup><col style="width:22%"><col style="width:43%"><col style="width:35%"></colgroup>
    <thead><tr><th scope="col">组件</th><th scope="col">职责</th><th scope="col">边界</th></tr></thead>
    <tbody><tr><td>采集层</td><td>收集并标记证据来源</td><td>不自动决定业务结果</td></tr></tbody>
  </table>
</div>
```

只有显式 `data-rfh-resizable` 的简单表会显示“调整列宽”。展开后，原生滑块支持拖动、方向键及 Home / End；每列独立调整，较宽时继续在原容器内滚动，不挤压相邻列。通常范围为 120–960 CSS 像素；若作者默认列宽超出该范围，保留这个初始边界。提供恢复默认，不保存到存储，也不影响其他表或主题。刷新后恢复作者默认，打印恢复适应纸宽。

增强仅支持 2–8 列、一个表头行、一个等长 colgroup、没有跨行/跨列或嵌套表的结构。不符合时保留原表，不注入失真的控件。复杂表需另外设计和验收，不自动拆表。控件只在 JavaScript 可用时出现；默认列宽、内容和滚动语义由 HTML/CSS 保证。

## 验证

- 用内容不均衡的三列表和长路径表，检查默认列宽不是被 `1%` 挤压；窄屏只有表内滚动，页面不横向溢出。
- 在约 1440px / 390px、浅色和深色下核对长文本、列标题及控件；从折叠证据打开后再调整；窗口变化后恢复默认。
- 实际用鼠标和键盘调整不同列，核对其他列不被偷偷压缩、重置恢复原比例；检查焦点、名称和原生表头关系。真实触屏和屏幕阅读器未测时明确保留为未验证，不把原生控件等同于已通过全平台验收。
- 检查调整后的打印及禁用 JavaScript 的阅读状态。单元测试和模拟 DOM 不替代真实浏览器尺寸、视觉及辅助技术验收。
