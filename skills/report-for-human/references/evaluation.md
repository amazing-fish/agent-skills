# 维护时的轻量验证

> 本机修改于 2026-11-02：增加用户认可范例的迁移检查；不把颜色统一当质量指标。

改动技能后，运行 skill-creator 的 `quick_validate.py`，核对 `agents/openai.yaml`，实际执行有变动的脚本。主文保持简短；参考材料只按需加载。

阅读工具回归：在系统为暗色、无历史选择时确认仍为认可的浅色；点击按钮实际切换配色，切回恢复原值，刷新记住选择。用包含空格、中文和 `#` 的文件名核对复制路径；浏览器拒绝剪贴板时显示选中路径且不误报成功。自动检查可替换剪贴板边界以保护用户现有剪贴板，须说明没有实际修改系统剪贴板。检查两种主题模板、自定义输出、390px 及无脚本打印；不能只检查按钮是否存在。

来源路径回归须模拟托管/sandbox 预览地址：用同一报告分别从本机文件与隔离的预览 URL 打开，两处都复制生成器记录的真实来源路径。覆盖显式 `--source-path` 与最终输出不同、重新落盘后改绑、未绑定时不复制预览 URL；只测 `file://` 不足以验收。模板保持未绑定状态，不能写入技能安装目录作为交付位置。

涉及业务决策截图规则时，检查有图与缺图两种材料，并续跑同一事项的探索或复测：截图须对应判断且来源可查；缺图条目须保存文字证据、限制、原因与下次补采内容，续跑先提醒，补采核对前不关闭。报告截图或模拟图不得冒充业务截图。无图时应能继续交付带明确限制的文字报告；这类说明改动不要求重跑未受影响的页面渲染矩阵。

选择两到三个原始任务覆盖本次变化，优先复用真实 PR/差异与原始运行记录：至少一个改动任务，以及要求/现状/机制中的另一类任务。涉及证据复用时覆盖相同树的新合并提交与真实输入变化；涉及发布时覆盖上传受理但尚未核验的状态。给独立执行者技能路径、原始仓库/差异和用户任务；不给预期结论、既有报告或缺陷提示。只要求创建报告，不改产品、不联系他人、不操作真实设备。

评估实际 HTML 和执行证据：

- 仅看首屏，能否复述改动结果、判断及最重要限制？
- 不懂该仓库的工程师，能否从一个具体场景理解前后行为？
- 默认是否只保留必要内容；可见小标题是否不超过三个；不阻断的细节是否按需展开？长度目标不应挤掉成立的风险。
- 展开证据后，能否定位同一版本的依据？来源、运行环境和未覆盖范围是否真实？
- 复用结果是否保留原版本/时间及等价依据？新 base/head 是否有实际 delta 复核，而非只替换报告标签？
- 交互/性能结论是否有对应操作和可比较的测量？包上传、注册表核验及上游接受是否被分别表述？
- 已确认阻断项、重大证据缺口是否可见；遗留问题与本次回归是否分开；干净改动是否被强造发现？
- 删除某段内容是否会改变判断或妨碍理解？若不会，删去并复测。

保留真实观察到的结果。只运行静态检查时不得声称技能端到端通过；没有模型对照实验时不得宣称质量或效率提升百分比。正常使用技能生成报告不必重跑本维护评估。

审美迁移还须检查：执行者是否实际复用所选范例（蓝色生成器或运维 HTML），首屏比例是否与该范例一致、主视觉是否表达关系而非文字卡墙、390px 下是否仍可读。用户只授权以好报告进化技能时，核对原报告字节未变；另用新任务检查范例能否迁移，不把原场景的成功、日期或权限结论带过去。使用无父会话上下文的执行者，只给技能路径和原始任务材料；不给预期判断或父 Agent 已生成的报告。静态策略测试不能代替这些生成与渲染观察。
