# 从已认可的部署报告学习

本机补充，2026-11-02。设计来源是用户认可的“鲸鲸部署与记忆兼容报告”：用户明确说“原报告很好，希望用原报告进化这个技能”。原报告采用自建 HTML，并未使用此技能；这里沉淀其做法，不改写原件，也不倒称原报告使用了此技能。

## 复用什么

先查看 `assets/operations-report.html` 与 `assets/operations-preview.png`。HTML 是去项目化的虚构样例，可复制到实际交付位置后编辑；不是实测证据。它保留原报告的米白底、墨绿文字、柔和的分层色、宽松留白与问题驱动的阅读顺序，并补上暗色、焦点和打印展开支持。

| 读者的问题 | 原报告有效的表达 | 迁移边界 |
| --- | --- | --- |
| 现在能用了吗 | 结果标题 + 一句影响 + 明确部署状态条 | 代码完成、测试通过、线上启用与最终配置验收分别取证；未部署就写未部署 |
| 到底变了什么 | 之前/现在并排，把身份与任务放在不同层 | 图展示真实输入和流向，角色英文只留必要标识，不把类名堆成架构图 |
| 两套系统会打架吗 | “档案室/经验本”这类熟悉比喻 + 各自职责/适用范围 | 比喻后说明真实权限与数据边界；可以并存不等于推荐自动启用 |
| 凭什么说完成 | 短验收行，线上结果与部署前测试分开 | 次要日志、哈希和复现步骤折叠；会改变判断的限制仍放正文 |

首屏的三张事实卡只有在分别回答独立问题时才保留，例如“改动位置、原数据是否保留、插件是否启用”；没有这些问题就删除，不能为凑版式填数字。最多围绕三个读者问题组织正文；简单问题只保留其中一个。不把状态条、事实卡和正文写成三遍同一结论。图中每张卡表达层级、差异或职责，不能只是段落加边框。

## 建议与执行分开讲清

“是否推荐开启 X，推荐就适配”包含一个决策和一个有条件的行动。先根据收益、现有能力和实际边界给出明确建议。推荐并且条件成立时，完成已授权的适配与回读，再写实际开启范围和验证；不推荐时说清当前保持什么、哪项条件欠缺。不要用“可以兼容”代替建议，也不要把只分析写成已适配。

## 错误例、正确例与判据

- 错误：用户肯定现有报告，便按技能默认蓝色主题重做原件。正确：保留原件，新增经脱敏的设计范例，将下一份真实汇报迁移到该范例。判据是用户要学习成功做法，还是明确要求改版。
- 错误：复制“已上线、全部通过”和旧时间来获得完整外观。正确：新报告依据新输入标明“本地通过、线上未验收”；可不填不适用区块。判据是当前证据，不是模板槽位。
- 错误：所有地方都用“档案室/经验本”。正确：只在读者需要理解两个系统的职责时选贴切比喻，紧跟实际边界。判据是能否帮助判断，而不是词语一致。

## 迁移与检查

复制样例到交付位置；替换标题、品牌、日期、人物、各项状态、正文和来源。全局检索“虚构/示例”确认没有残留模板事实，也不能只删除模拟标记而保留虚构成功。

保留窄屏单列、可手动切换的暗色、键盘焦点与打印展开。正文采用至少 16px，证据辅助文字可稍小；深浅底色与字色成对设置。报告无需 JavaScript 即可读懂；打印样式也应在禁用脚本时展开凭据。

2026-11-02 用户补充：每份报告必须有明暗切换和文件位置复制。浅色画布与正文分别沿用原报告 `#f4f4ef` / `#193b39`，默认浅色，暗色改为手动选择并记忆；复用共用控件，不另写一套。这里的主题属性是 `data-report-theme`，系统暗色媒体查询不能覆盖用户的浅色选择。2026-11-03 再次纠正：预览地址可能是 sandbox，文件位置必须采用落盘时绑定的真实绝对路径；运维 HTML 复制到交付位置后必须运行共用脚本完成绑定。复制失败要提供可选中的真实路径。

当前三态约定：保留默认浅色，增加显式“跟随系统”选项；浅色/深色不随系统变化，跟随系统实时更新。三态选择均可记忆，复用共用控件，不另写实现。

运行实际桌面/手机、三态选择与明暗主题、折叠键盘操作和打印检查；检查无远程资源。截图证明版式，不证明部署或记忆隔离。范例的 CSS 可以复用，任何业务事实都不可直接继承。
